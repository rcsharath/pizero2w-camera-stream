# Challenge 5.4: Successor Objections

Objective: Identify points in handoff artifacts (`DEPLOY.md`, `README.md`, directory layout) where a successor would be unable to proceed, copy files to the wrong path, or encounter command failures.

1. **Uncreated target directory for user systemd unit scp**
   - Source Line: `scp -o "KexAlgorithms=curve25519-sha256" camerastream.service rcsharath@rcsharathpi.local:/home/rcsharath/.config/systemd/user/camerastream.service`
   - Misleading Point: If the directory `/home/rcsharath/.config/systemd/user/` has not been created on the Pi prior to execution, `scp` fails with `scp: /home/rcsharath/.config/systemd/user/camerastream.service: No such file or directory`.
   - Fix Needed: Add remote `mkdir -p ~/.config/systemd/user` step prior to `scp`.

2. **Directory nesting risk during recursive scp of static folder**
   - Source Line: `scp -r -o "KexAlgorithms=curve25519-sha256" static rcsharath@rcsharathpi.local:/home/rcsharath/camerastream/`
   - Misleading Point: When `/home/rcsharath/camerastream/static` already exists on the remote target, some `scp` implementations copy `static` inside it, resulting in nested `/home/rcsharath/camerastream/static/static/index.html`.
   - Fix Needed: Clarify target path or use trailing slash syntax (`static/`).

3. **Systemd DBUS environment variable missing in non-interactive SSH**
   - Source Line: `systemctl --user daemon-reload`
   - Misleading Point: Executing `systemctl --user` commands via non-login SSH sessions can fail with `Failed to connect to bus: No such file or directory` unless lingering is enabled or `export XDG_RUNTIME_DIR=/run/user/$(id -u)` is set.
   - Fix Needed: Mention running inside an interactive login shell or setting `export XDG_RUNTIME_DIR=/run/user/$(id -u)`.

4. **Hardcoded user path in service file vs README instructions**
   - Source Line: `cp camerastream.service ~/.config/systemd/user/`
   - Misleading Point: `camerastream.service` hardcodes `ExecStart=/usr/bin/python3 -u /home/rcsharath/camerastream/stream_server.py` and `WorkingDirectory=/home/rcsharath/camerastream`. A successor deploying under a different username will encounter immediate service failure unless alerted to the username assumption.
   - Fix Needed: Note that the unit assumes user `rcsharath` and path `/home/rcsharath/camerastream`.
