# Challenge 3.6: Literalist Objections

Objective: Identify discrepancies between Phase 3 Design Decisions and the implementation in `stream_server.py`.

1. **Unrequested param_name argument in clamp_gain helper**
   - Design Rule: "`red`, `blue` parseable as float; then clamped into `[1.0, 3.0]`"
   - Code: `def clamp_gain(gain_val, param_name="gain"):`
   - Objection: The design decisions specified pure clamping logic for gain parameters. The added optional `param_name` parameter and formatted error string `f"Invalid {param_name} parameter..."` were not requested in the design specification.

2. **Divergence in ROI non-string handling message during load_state**
   - Design Rule: "Then validate every loaded key with the same validators used by the endpoints; drop any individual key that fails validation, keep the rest, and print one line per dropped key."
   - Code:
     ```python
     else:
         print(f"[State] Dropping invalid 'roi' key: value '{val}' is not string or null")
     ```
   - Objection: For non-string non-null ROI values in `state.json`, `load_state` prints a custom message rather than catching and printing a `ValueError` raised directly by `validate_roi`.

3. **Strict zero check on lower bounds without float epsilon tolerance**
   - Design Rule: "Float comparisons on the two sum rules use a tolerance of 1e-9 so that 0.3 + 0.7 is accepted."
   - Code:
     ```python
     if x < 0.0:
         raise ValueError(f"Invalid ROI x='{x_val}'; must be >= 0.0")
     ```
   - Objection: The design decision explicitly specified `1e-9` tolerance for sum rules (`x + w <= 1.0` and `y + h <= 1.0`). The code applies `-1e-9` tolerance only to upper sum bounds, leaving strict `< 0.0` checks on lower bounds that could reject tiny negative floating point imprecisions like `-1e-12`.

4. **Missing explicit handle_request documentation string**
   - Design Rule: "Every read or write of the shared globals inside a request handler happens while holding camera_lock. Acquire it, validate, mutate, snapshot the values you need for the response, set restart_requested, release, then write the response outside the lock."
   - Code: `def handle_request(self, is_head=False):`
   - Objection: The helper method `handle_request` combines `do_GET` and `do_HEAD` path dispatch and lock management but lacks an explicit docstring stating the atomic lock release protocol defined in the design decisions.
