# Challenge 3.5: Falsifier Objections

Objective: Identify concrete parameter sets that either (a) pass validation but produce invalid/problematic `rpicam-vid` argv, or (b) are refused despite being legal camera settings in `rpicam-vid`.

1. **Refusal of valid ROI width below 0.05 threshold**
   - Query string: `?x=0.0&y=0.0&w=0.03&h=0.05`
   - Issue: `validate_roi` enforces `0.05 <= w <= 1.0`. A width of 0.03 (3% of sensor) is refused with HTTP 400 even though `rpicam-vid` accepts sub-5% ROI crops for high-magnification hardware zoom.

2. **Silent gain clamping mutates input without caller awareness**
   - Query string: `?mode=custom&red=0.5&blue=1.4`
   - Issue: `clamp_gain` silently clamps `red=0.5` to `1.0` instead of rejecting or notifying the client that `0.5` was modified. Furthermore, `rpicam-vid --awbgains` permits red/blue gains below 1.0 for specific lighting environments.

3. **Silent upper gain clamping caps high ISP gains**
   - Query string: `?mode=custom&red=3.5&blue=1.4`
   - Issue: `clamp_gain` clamps `red=3.5` to `3.0`. `rpicam-vid` hardware ISP supports gain values above 3.0 (up to 8.0 or higher in custom ISP profiles), so clamping to 3.0 artificially caps valid high gain values without returning an error.

4. **Refusal of higher frame rates at lower resolutions**
   - Query string: `?fps=40`
   - Issue: `validate_fps` enforces `5 <= fps <= 30` and returns HTTP 400 for `fps=40`. However, lower resolutions such as 640x480 and 320x240 natively support 40-60 FPS on the OV5647 sensor under `rpicam-vid`.

5. **Refusal of 90/270 degree rotation queries**
   - Query string: `?rot=90`
   - Issue: `validate_rotation` restricts valid values to `{"0", "180", "hflip", "vflip"}` and rejects `rot=90` with HTTP 400. While OV5647 hardware ISP does not support 90-degree transpose, clients attempting this parameter receive a generic 400 error rather than a specific hardware limitation explanation.
